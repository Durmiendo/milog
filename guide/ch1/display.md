Рисование устроено как вывод текста: команды копятся в буфере, `drawflush` отправляет их на дисплей одним пакетом.

```
draw clear 0 0 0
draw color 247 206 116 255
draw rect 40 40 96 96
drawflush display1
```

| Команда | Аргументы |
| --- | --- |
| `clear` | цвет фона: красный, зелёный, синий |
| `color` | цвет кисти: красный, зелёный, синий, прозрачность |
| `stroke` | толщина линии |
| `line` | начало и конец: x1, y1, x2, y2 |
| `rect` | заливка: x, y, ширина, высота |
| `lineRect` | контур: x, y, ширина, высота |
| `poly` | многоугольник: x, y, число сторон, радиус, поворот |

Начало координат в левом нижнем углу. Логический дисплей имеет сторону 176 точек, большой дисплей 176 тоже, но с другим масштабом на карте.

Порядок важен: каждая команда рисует поверх предыдущих, а `color` действует на все последующие фигуры до следующей смены цвета.

Буфер ограничен, поэтому `drawflush` ставят в конце каждого кадра, а не раз в несколько проходов.

## Задача

Залейте дисплей чёрным и нарисуйте оранжевый квадрат 96 на 96 в центре.

Ограничения:

- всего не больше пяти инструкций.

<Proc lesson="ch1-display">
<World>

```mock
display size:176
```

```tests
req mock display1 commands contains [clear,color,rect] <"Нужны clear, color и rect">;
req code uses drawflush <"Без drawflush картинка не появится">;
limit instruct 5 <"Не больше пяти инструкций">;
```

</World>
</Proc>

::: details Решение

```
draw clear 0 0 0
draw color 247 206 116 255
draw rect 40 40 96 96
drawflush display1
```

:::

Картинка появляется по кнопке `mocks`, блок `display1` рисует холст вживую. Если экран пустой, а проверка красная, скорее всего забыт `drawflush`.
