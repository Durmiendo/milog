До сих пор процессор работал с собственными числами. Настоящая автоматика начинается с чтения чужого состояния.

```
sensor приёмник блок @свойство
control свойство блок значение
```

`sensor` читает свойство блока: `@enabled` для включённости, а на карте ещё `@copper`, `@totalItems`, `@health` и остальные. Результат это число, для флагов это 1 или 0.

`control` задаёт свойство: `enabled` включает и выключает блок, `shoot` и `color` управляют турелями и подсветкой. Имя свойства пишется без `@`.

Из пары `sensor` и `control` собирается любой автомат: прочитать вход, посчитать решение, выставить выход.

## Задача

Тумблер `switch1` это вход, тумблер `switch2` это выход. Повторите состояние входа на выходе.

Ограничения:

- состояние читается датчиком, а не подставляется числом;
- всего не больше трёх инструкций.

<Proc lesson="ch1-switch">
<World>

```mock
switch enabled:true
switch enabled:false
```

```tests
req mock switch2 enabled equals true <"switch2 должен повторить состояние switch1">;
req code uses sensor <"Состояние читается через sensor">;
req code uses control <"Состояние задаётся через control">;
limit instruct 3 <"Не больше трёх инструкций">;
```

</World>
</Proc>

::: details Решение

```
sensor state switch1 @enabled
control enabled switch2 state 0 0 0
```

:::

Холст пустой, инструкции добавляются кнопкой `add block`.

Проверьте схему на втором состоянии. Откройте `mocks`, вызовите у `switch1` метод `toggle` и запустите процессор: выход должен погаснуть следом за входом. Проверка задания при этом станет красной, это ожидаемо, она смотрит на включённое состояние.
