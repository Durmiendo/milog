Переменные процессора живут внутри процессора. Соседние схемы их не видят, и при перезапуске они начинаются заново. Общее хранилище это ячейка памяти.

```
write значение cell1 адрес
read приёмник cell1 адрес
```

Ячейка памяти `cell1` хранит 64 числа с адресами от 0 до 63, банк `bank1` хранит 512. Хранятся только числа, текст туда не положить.

Порядок аргументов у `write` и `read` разный: `write` начинается с того, что пишем, `read` начинается с того, куда читаем. Перепутанные аргументы это вторая по частоте ошибка после забытого шага цикла.

Запись за границу памяти игнорируется, чтение за границей возвращает ноль.

## Задача

Заполните ячейки с 0 по 9 квадратами их адресов: в ячейке 0 должен лежать 0, в ячейке 5 значение 25, в ячейке 9 значение 81.

Ограничения:

- подготовка и `end` уже стоят, менять их нельзя;
- заполнение делается циклом;
- всего не больше семи инструкций.

<Proc lesson="ch1-memory">
<World>

```mock
cell size:64
```

```code
set i 0 #lock move edit
end #lock move edit
```

```tests
req mock cell1 data[0] equals 0 <"В ячейке 0 должен лежать 0">;
req mock cell1 data[5] equals 25 <"В ячейке 5 должно лежать 25">;
req mock cell1 data[9] equals 81 <"В ячейке 9 должно лежать 81">;
limit instruct 7 <"Не больше семи инструкций">;
```

</World>
</Proc>

::: details Решение

```
set i 0
op mul sq i i
write sq cell1 i
op add i i 1
jump 1 lessThan i 10
end
```

:::

Содержимое памяти видно по кнопке `mocks`, блок `cell1` показывает сетку адресов. Заполненные ячейки подсвечиваются, поэтому ошибку в адресации видно сразу.
