Итоговая задача главы собирает всё вместе: память, текст и графику в одном проходе.

Полоса заполнения считается пропорцией. Уровень задан в процентах, ширина дисплея 176 точек, значит множитель равен 1.76.

```
op mul width level 1.76
```

Такой множитель лучше вынести в отдельную строку, чем прятать в аргумент `draw`: при смене размера дисплея правится одно место.

## Задача

Соберите индикатор заряда.

Требования:

- записать `level` в ячейку 0 памяти `cell1`;
- вывести в `message1` строку `Заряд: 63%`;
- залить дисплей фоном и нарисовать горизонтальную полосу от левого края, длина полосы равна `level` в масштабе дисплея;
- строку с исходным значением и `end` менять нельзя;
- всего не больше двенадцати инструкций.

<Proc lesson="ch1-indicator">
<World>

```mock
cell size:64
display size:176
message
```

```code
set level 63 #lock move edit
end #lock move edit
```

```tests
req mock cell1 data[0] equals 63 <"Уровень не записан в ячейку 0">;
req mock message1 text equals "Заряд: 63%" <"В блоке сообщений должно быть: Заряд: 63%">;
req mock display1 commands contains [clear,rect] <"На дисплее нет фона и полосы">;
req code uses drawflush <"Без drawflush картинка не появится">;
limit instruct 12 <"Не больше двенадцати инструкций">;
```

</World>
</Proc>

::: details Решение

```
set level 63
write level cell1 0
print "Заряд: {0}%"
format level
printflush message1
op mul width level 1.76
draw clear 20 20 20
draw color 247 206 116 255
draw rect 0 72 width 32
drawflush display1
end
```

:::

## Что дальше

Схема считает уровень из константы. В игре его источником будет `sensor`: заряд батареи, заполнение хранилища, здоровье турели. Замена одной строки превращает учебный индикатор в рабочее табло.

Открытые вопросы, к которым вернёмся в следующей главе: как не пересчитывать кадр каждый такт, как разделить длинную схему на несколько процессоров и как хранить в памяти не одно число, а таблицу состояний.
