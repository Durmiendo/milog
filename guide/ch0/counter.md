Процессор помнит только одно: номер следующей строки. Он лежит в системной переменной `@counter`.

Такт выглядит так:

1. взять строку с номером `@counter`;
2. увеличить `@counter` на единицу;
3. выполнить строку.

Если `@counter` уходит за последнюю строку, он сбрасывается в ноль. Отсюда бесконечный круг исполнения.

`@counter` доступен на запись как обычная переменная. Запись в него это и есть переход:

```
set @counter 7
```

Следующей выполнится строка 7. Никакой отдельной магии у перехода нет, `jump` из следующего урока делает ровно то же самое.

## Задача

Строка `set answer 0` обнуляет ответ. Удалить её нельзя. Сделайте так, чтобы она никогда не выполнялась, а `answer` остался равен 1.

Ограничения:

- обе исходные строки остаются на месте;
- `jump` пока не используем, работаем через `@counter`;
- всего не больше трёх инструкций.

<Proc lesson="ch0-counter">
<World>

```code
set answer 1 #lock move edit
set answer 0 #lock move edit
```

```tests
req var answer equals 1 <"answer должен остаться равен 1">;
req code avoids jump <"В этом уроке jump не нужен">;
limit instruct 3 <"Не больше трёх инструкций">;
```

</World>
</Proc>

::: details Решение

```
set answer 1
set @counter 3
set answer 0
```

:::

Строка 1 отправляет счётчик на адрес 3. Такой строки нет, счётчик сбрасывается в ноль, и строка 2 остаётся недостижимой. Она занимает место в коде, но не тратит такты.

Обратите внимание на хрупкость приёма: любая вставка строки выше сдвигает адреса, и переход попадёт не туда. Поэтому в реальных схемах адрес перехода задают через `jump`, который умеет держаться за конкретный блок.
