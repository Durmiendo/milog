Цикл это переход назад. Состав всегда одинаковый:

1. подготовка: начальное значение счётчика;
2. тело: полезная работа;
3. шаг: изменение счётчика;
4. условие: переход назад на начало тела, пока условие выполняется.

Забытый шаг превращает цикл в вечный: счётчик не меняется, условие остаётся верным, процессор крутится на месте. Это самая частая ошибка в логике.

Цена цикла считается в тактах. Тело из трёх инструкций на десяти повторах это тридцать тактов. Процессор выполняет фиксированное число инструкций за игровой тик, поэтому длинный цикл заметно замедляет схему.

## Задача

Посчитайте сумму чисел от 1 до 10 и положите её в `sum`.

Ограничения:

- подготовка и `end` уже стоят, менять их нельзя;
- сумма считается циклом, а не одним числом;
- всего не больше шести инструкций.

<Proc lesson="ch0-loop">
<World>

```code
set sum 0 #lock move edit
set i 1 #lock move edit
end #lock move edit
```

```tests
req var sum equals 55 <"sum должен быть равен 55">;
req code uses jump <"Цикл строится на jump">;
limit instruct 6 <"Не больше шести инструкций">;
```

</World>
</Proc>

::: details Решение

```
set sum 0
set i 1
op add sum sum i
op add i i 1
jump 2 lessThanEq i 10
end
```

:::

Запустите `auto` и уменьшите `ips` до единицы, чтобы увидеть проход по кругу. После `end` подготовка выполняется заново, `sum` обнуляется и набирается снова. Схема, которая должна считать один раз, обычно заканчивается не на `end`, а на переходе в собственную точку ожидания.
