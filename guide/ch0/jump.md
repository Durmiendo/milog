`jump` это условная запись в `@counter`.

```
jump адрес условие первый второй
```

Если условие выполнено, счётчик получает указанный адрес, иначе процессор идёт на следующую строку.

| Условие | Проверка |
| --- | --- |
| `equal` | равно |
| `notEqual` | не равно |
| `lessThan` | меньше |
| `lessThanEq` | меньше или равно |
| `greaterThan` | больше |
| `greaterThanEq` | больше или равно |
| `always` | всегда |

Ветвление строится через переход вперёд: условие пропускает кусок кода, который не должен выполняться.

Инструкция `end` сбрасывает счётчик в ноль и начинает программу заново. Её ставят в конец, чтобы было куда прыгать при выходе из ветки.

## Задача

Положите в `result` большее из значений `a` и `b`.

Ограничения:

- исходные строки и `end` менять нельзя;
- нужен хотя бы один `jump`;
- всего не больше шести инструкций.

<Proc lesson="ch0-jump">
<World>

```code
set a 12 #lock move edit
set b 25 #lock move edit
end #lock move edit
```

```tests
req var result equals 25 <"result должен содержать большее значение">;
req code uses jump <"Нужен блок jump">;
limit instruct 6 <"Не больше шести инструкций">;
```

</World>
</Proc>

::: details Решение

```
set a 12
set b 25
set result a
jump 5 greaterThanEq result b
set result b
end
```

:::

Разберите решение по тактам. Если `a` уже больше, переход уводит счётчик на строку 5, и присваивание `set result b` пропускается. Если нет, процессор просто идёт дальше и перезаписывает `result`.

Проверьте себя: замените в решении `greaterThanEq` на `lessThan` и посмотрите, как проверка станет красной. Условие перехода всегда описывает случай, когда код нужно пропустить.
