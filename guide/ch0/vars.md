`set` копирует значение, а не связывает переменные. После `set b a` переменная `b` получает текущее значение `a` и дальше живёт отдельно.

Из этого следует главное ограничение: прямая перестановка значений теряет данные.

```
set a b
set b a
```

Первая строка затирает старое `a`, поэтому вторая строка вернёт в `b` то же самое значение. Нужна третья переменная, куда убирается копия.

## Задача

Поменяйте значения `a` и `b` местами: в `a` должно оказаться 12, в `b` должно оказаться 5.

Ограничения:

- строки с исходными значениями менять нельзя;
- подставлять числа руками нельзя, разрешено только копировать переменные;
- всего не больше пяти инструкций.

<Proc lesson="ch0-vars">
<World>

```code
set a 5 #lock move edit
set b 12 #lock move edit
```

```tests
req var a equals 12 <"a должно стать равно 12">;
req var b equals 5 <"b должно стать равно 5">;
limit instruct 5 <"Не больше пяти инструкций">;
```

</World>
</Proc>

::: details Решение

```
set a 5
set b 12
set temp a
set a b
set b temp
```

:::

Имя `temp` ничем не выделено, это обычная переменная. Процессор не различает служебные и рабочие имена, разделение существует только в голове автора схемы.
